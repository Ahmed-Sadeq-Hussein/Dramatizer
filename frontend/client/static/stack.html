The stack

What happens between your click and the voice you hear: each layer a request passes through, what it is built with, and how much it handled in the stress test of 25 November 2026.

Your browser your device

One page, plain HTML, CSS and JavaScript, no framework and nothing loaded from other sites. It talks to the server only through the Dramatizer's JSON API.

  • HTML / CSS / JavaScript
  • Web Audio (recording a voice)
  • JSON API, version 1

Cloudflare the internet

app.dramatizer.dev points to Cloudflare. It holds the public certificate, absorbs floods, and sends the traffic down an outgoing tunnel, so the home router has no open port.

  • Cloudflare DNS and TLS
  • Cloudflare Tunnel (cloudflared, in a container)

Front door container

A small forwarder that always sends traffic to whichever version is live. Releasing or rolling back changes one line in its state file; it never holds the site's keys and never reads the traffic.

  • Python 3.12, asyncio
  • blue / green switch

Stress test: ~260 new connections a second on two CPUs, no errors with 1024 at once.

Web server and API app container

The Dramatizer itself: accounts, the user agreement, the job queue, voices, genomes, ratings, results and the chatbot's tools. HTTPS all the way to here.

  • Python 3.10
  • Flask 3
  • Werkzeug, threaded
  • PBKDF2 passwords, hashed session tokens
  • MCP server (the same calls for AI tools)

Stress test: ~550 simple requests a second, ~160–200 for logged-in lists; logins ~16 a second (7 before the fix that checks passwords outside the database lock).

Voice and language models GPU

CosyVoice 3 clones the voice from a short reference and speaks the line; the genome (stress, pauses, sighs, speed) shapes how it is said. Gemma answers "Ask the Dramatizer" with tools that look up the real records.

  • CosyVoice 3 (0.5B)
  • Gemma 4 E4B, 4-bit
  • PyTorch, CUDA 12
  • NVIDIA RTX 3080, 10 GB

Stress test: the bottleneck. About 1 s of GPU per second of speech, so ~10 medium lines a minute; renders are 1.9× slower while the chatbot answers. Both models fill 9.7 of 10 GB.

Measuring app container

What the Lab, the genome searches and the release checks measure: does the speech say the words, does it sound like the voice, and is it good audio.

  • Whisper (word error rate)
  • speaker embeddings (similarity)
  • quality scores
  • BM25 search over the records (chatbot)

Stress test: reading a 30-second upload takes 3–10 ms; oversized files are refused before decoding.

Storage Docker volume and disk

Accounts, sessions, ratings and the audit log live in one database; audio, renders and charts are files. Models and the voice pack are mounted read-only.

  • SQLite (WAL)
  • Docker volumes
  • read-only model and voice mounts

Where it runs

  • One home PC: Windows 11, 16 CPU threads, RTX 3080
  • Docker Desktop on WSL 2, NVIDIA container runtime
  • Every part in its own container, restarted on failure

How a release goes live

  • GitHub Actions runs the tests and checks the image holds no secrets
  • A large base image (CUDA, models' libraries) and a small app image on top
  • The new version starts beside the live one and must pass a smoke test: login, a render scored by Whisper, the chatbot
  • Then the front door switches; rolling back is the same switch

Scaling next

  • The GPU limits everything: the chatbot off the render GPU, caching repeated lines
  • A shared job queue, then one render worker per GPU
  • A production web server when traffic needs it
